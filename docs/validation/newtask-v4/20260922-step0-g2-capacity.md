## 〇、先说结论（三条重要发现）

1. **计划 2.7 ② 那张表（以及 `scripts/README.md` 2.2 节第 5 条）的"hard `bin=15` 实际放下 9~12 个"是错的，真实只有 4~8 个（均值约 5.5）。**
   原因：`spawn_random_bin` 的 `min_gap` 被**加了两次**——障碍容器进 `avoid` 时 `_push_actor_as_obb2d(item, min_gap)` 给障碍 OBB 半边加 `min_gap`，
   新容器的判据又是 `dist < bin_half_size + min_gap`；且障碍 OBB 用的是 trimesh 实测外廓半边 **0.03**（不是 0.0275）。
   轴对齐时中心最小距 = 0.03+0.04+0.0275+0.04 = **0.1375**，不是计划写的 0.095。
   **真实环境校准**（`gym.make(..., difficulty="hard")` 只 reset，种子 0~7）：
   VideoUnmask 放下 `[6,5,5,6,6,5,5,6]`，ButtonUnmask `[5,4,6,6,6,5,5,6]`；最近两容器中心距 0.139~0.180，全部 ≥0.1375。
   蒙特卡洛同配置给 5.55（Video）/ 5.18（Button），与真实一致。**现 region + `min_gap_factor=2` 下饱和容量约 5~6 个，请求 10 个时"全部放下"率 0%。**
2. **VideoRepick 的方块障碍 OBB 约一半以上是退化的（一根轴投影成零向量 ⇒ 障碍变成一条长 0.04 的线段）。**
   `get_actor_obb` 用 trimesh `bounding_box_oriented`，对正方体经常把竖直轴排在第 0/1 列，`_trimesh_box_to_obb2d` 取 `R[:2,0]`/`R[:2,1]` 时那一列投影为零、`_safe_unit` 原样返回零向量。
   trimesh 复刻 2000 个随机 yaw：退化 48.9%；**真实环境 VideoRepick hard 4 个种子 60 块：退化 42/60 = 70%**。
   后果：方块实际间距常小于名义 `min_gap=0.02`（N=15 时 94% 的布局存在间距 <0.02 的方块对，中位最小间距 0.0098 m，最小 0.0002 m；未见重叠）。容器（bin）的 OBB 不退化（外廓 0.06×0.06×0.072，h=[0.03,0.03]，真实环境同样确认）。
3. **VideoRepick 放置不是瓶颈（N≤15 全部放下 100%），真正约束 clutter 数量的是 swap 穿越旁观块的风险**：即便 N=6，按钟形轨迹逐帧采样，每局（8~12 次交换）至少一次扫到旁观块的比例已达 41.5%。D5 几何检查是本环境前置（计划 2.13 已写），且以此看 D5 的拒绝率会很高。

## 一、判据来源（与源码等价的地方）

| 对象 | 判据 | 源码锚点 |
|---|---|---|
| 容器采样区 | 中心 ± (`region_half_size` − 0.0275) 均匀采样，`bin_half_size=(cube_half·2.5+0.005)/2=0.0275` | `utils/object_generation.py::spawn_random_bin` |
| 容器障碍 | 已放容器以 actor 进 `avoid`，OBB = trimesh 外廓（半边 0.03，随 yaw 旋转）**+ `min_gap`**；新容器按"中心到障碍 OBB 的点距 < 0.0275 + `min_gap`"拒绝 | 同上 + `_trimesh_box_to_obb2d`；`VideoUnmask::_load_scene` / `ButtonUnmask::_load_scene`（`avoid.append(bin_actor)`） |
| 容器 yaw | 通过拒绝后才抽 `u·90°` | `spawn_random_bin` |
| 失败处理 | `max_trials=256` 用尽抛 `RuntimeError`，环境 `except RuntimeError: break`（静默少放） | 两个 `_load_scene` |
| 按钮避让 | ButtonUnmask 先 `build_button`：中心 `[-0.2,0] + (U−0.5)·[0.1,0.1]`，返回预制 OBB 半边 `max(base_half)·1.5 = 0.025·1.5·1.5 = 0.05625`，**不加 pad** | `object_generation.py::build_button` / `create_button_obb` |
| `step_bin_scan` | `step` 里 `for i in range(step_bin_scan)` + `hasattr(self, f"bin_{i}")`，只对 `bin_0..bin_{scan-1}` 做揭示动画；容器数超过它的部分不参与揭示 ⇒ 若 N>15 必须同步抬 | `VideoUnmask::step`，`NATIVE_SAMPLING.parameters.step_bin_scan=15` |
| 方块区域 | 整片区域中心 `[-0.1,0]`、半边 `[0.2,0.25]`，采样区再收缩 `cube_half=0.02` | `VideoRepick.NATIVE_SAMPLING.positions.hard_cubes`（与 `BinFill.py` 的 `region_center/region_half_size` 相同，已核实） |
| 方块判据 | 新方块 OBB 半边 = 0.02 + `min_gap`(=`cube_half_size`=0.02) = 0.04，每次尝试都抽 yaw∈[0,2π)；障碍 = 按钮 OBB + 已放方块 actor（pad=0，**trimesh OBB，可能退化**）；SAT 逐字复刻 `_obb2d_intersect` | `object_generation.py::spawn_random_cube`；`VideoRepick::_load_scene` hard 分支 |
| 方块失败 | hard 分支抛 `SceneGenerationError` ⇒ reset 失败（与口径 14 "全部放下才算生成成功"一致） | `VideoRepick::_load_scene` |
| 交换 | 发起者 = [目标, 其余随机取 2 块]，第 k 次用 `init[k%3]`；搭档 = 交换开始时 XY 最近邻（严格小于、生成顺序优先）；轨迹 smoothstep + `lane_offset·sin(π·α)` 钟形法向偏移，A 走 +n、B 走 −n；结束时两块互换位姿 | `VideoRepick::step`、`utils/statechange.py::swap_flat_two_lane`（调用处 `lane_offset=0.07`）、`utils/bin_collision.py::nearest_partner_index` |

**等价性核对**：
- `real_fn_check.py` 直接调用源码里的 `spawn_random_bin` 函数体（只把 `build_bin`/`get_actor_obb` 换成同几何的 trimesh 桩），N=15：Video 5.5（4~7）、Button 5.25（3~7），与蒙特卡洛一致。
- `sat_batch`（向量化）与 `_obb2d_intersect` 逐字复刻版随机 3000 例比对，0 不一致。
- 随机数用 numpy 代替 `torch.Generator`，分布等价，不追求逐种子复现。

**口径说明**：Unmask 各 N 使用相同种子序列（公共随机数），所以当 N 远大于饱和容量时"放下个数"各列相同——这是预期，不是 bug。

### 2.5 间距缩小的物理代价（推导，未跑演示）

由判据可推出两容器真实外廓的**最小边距下界** ≈ `0.0275 + 2·min_gap − 0.0424`（0.0424 为外廓半边 0.03 旋转 45° 时的角点距）：
factor 2 ⇒ ≥0.065 m；factor 1 ⇒ ≥0.025 m；**factor 0.5 ⇒ 只剩 ≥0.005 m**。`solve_pickup_bin` 夹爪下探时能否不碰邻居**本次没测**（新行为未实现，不跑演示），factor 0.5 属高风险。

### 2.6 扩 region 与 B13 外环干扰容器的冲突

B13 的外环下界 `0.2675 = 0.20 + 0.0275 + 0.04` 是按**现 region 半边 0.2** 且按**单次 min_gap** 算的：
- region 扩到 0.25 ⇒ 下界应抬到 **0.3175**，外环宽度从 0.1825 缩到 0.1325（上界仍 0.45）；
- region 扩到 0.3 ⇒ 下界 **0.3675**，外环宽度只剩 0.0825；且 +x 侧相机可见只到 x≈0.43、x=0.4 处可见 y 仅 ±0.31，外环 +x 段基本出画 ⇒ 外环实际只剩 −x 与 ±y 三边；
- 另外按本报告发现 1，若干扰容器也走 `spawn_random_bin` 并把 region 内容器放进 `avoid`，真实需要的净距是"双 pad"口径，B13 的 0.2675 本身在现 region 下也偏紧（真实容器外廓 0.03、旋转后角点 0.0424）。**扩 region 必须同步重算 B13 外环。**

### 3.2 swap 穿越旁观块风险（**近似指标**）

旁观块外廓 = 其 OBB 半边 `0.02 + 0.005` 余量。两种近似：
- **(a) 两车道矩形**：沿 AB 方向 `[−0.02, L+0.02]`、法向 `±(0.07+0.02)` 的矩形（把两条车道的钟形轨迹整体包住，偏保守）；
- **(b) 钟形轨迹采样**：按 smoothstep + `0.07·sin(πα)` 逐帧 41 点采样，移动块取起始 yaw 的 OBB（忽略四元数插值），更接近真实轨迹。

**题面口径**：每个成功布局随机取 3 个发起者，与其初始布局 XY 最近邻配对（不做顺序演化）：

| 单对扫到旁观块（b 轨迹） | 6.2% | 15.0% | 30.8% | 44.8% | 53.7% | 74.3% | 88.5% |
| 3 对中至少一对（a） | 30.5% | 52.5% | 77.0% | 88.0% | 96.0% | 99.5% | 100% |

**顺序模拟口径**（更贴近运行时：n_swaps 均匀取 8~12，第 k 次发起者 `init[k%3]`，搭档在当前位置上重算最近邻，交换后位姿互换）：

| 每次交换扫到（b） | 8.7% | 21.8% | 28.7% | 44.9% | 57.5% | 72.8% | 86.7% |

## 五、附带发现，建议另立待决项（不在本次范围内修）

1. 计划 2.7 ② 表与 `scripts/README.md` 的"9~12"要改为真实值（4~8，均值约 5.5）；2.8 字段表"实际只放下 9~12"同理。
2. `spawn_random_bin` 的 `min_gap` 双计 + 用 0.0275 采样但障碍外廓 0.03，属于原实现语义，按口径不改；但新值规格冻结/核验若另写几何判据，必须按此真实语义对齐，否则注入会与原判据不一致。
3. 方块 OBB 退化（`get_actor_obb` + `_trimesh_box_to_obb2d`）使 `spawn_random_cube` 的名义 `min_gap` 实际不保证；xhard 的 clutter 若沿用该函数，D5 的初态检查可能拒掉一部分原判据放出的布局（间距 <0.02），需要在 D5 余量上统一口径。

## 六、阶梯表（区域不动）

> 用户决定：Unmask 容器区域不动（中心 `[0,0]`、半边 0.2），只缩小间距。脚本 `ladder.py`，原始数据 `ladder_results.json`。
> 判据与第一节完全相同（`spawn_random_bin` 真实语义：`min_gap` 双加、障碍外廓半边 0.03、采样收缩 0.0275、`max_trials=256`、ButtonUnmask 含按钮区 0.05625 避让）。
> 每个 factor 200 种子。因为同一种子下"前 N 个"的随机抽取与请求更多个时完全相同（公共随机数），所以"请求 N 个全部放下" ⇔ "该种子饱和放置个数 ≥ N"，一次饱和放置即可得到所有 N 的全部放下率。
> 真实最小边距：取前 60 个种子的饱和布局，把每个容器按真实外廓（半边 0.03、随 yaw 旋转的正方形）算两两凸多边形最小距离，取布局内最小值；"理论下界" = `0.0275 + 2·min_gap − 0.03·√2`。

要点：
- 实测最小边距几乎贴着理论下界（最坏情况是两个容器都转到 45°、角对角），所以按"下界"理解即可。
- **factor ≤ 0.25 时判据本身允许容器外廓重叠**（障碍按 0.03 算、新容器却按 0.0275 算，再加上旋转角点 0.0424），生成出来就是穿模布局，**不可用**。可用的下限是 factor 0.5（边距 ≥ 5 mm）。
- ButtonUnmask 普遍比 VideoUnmask 少 1 个（按钮占掉约 0.11×0.11 m）。两环境若要同一个 N，以 ButtonUnmask 为准。
- 夹爪抓取对邻居的干涉**没有测**（不跑演示）。factor 0.75 的 15 mm、0.5 的 5 mm 是否够 `solve_pickup_bin` 下探，需要实现后做演示验证。
