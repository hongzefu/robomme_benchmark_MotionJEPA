# 验证留档的通用记录与比较规范

用于重要验收、回归、一致性判断的测试与生成，都须保留**可复现入口、实测文档与轻量证据**。
成功、失败、中断、超时与未覆盖项如实记录；只有聊天、终端输出或临时缓存不算留档完成。

## 运行编号与目录

每次重要运行用独立编号 `<UTC时间>-<主题>-<短源码版本>`，冲突加序号；非空输出拒绝覆盖。

```text
docs/validation/<主题>/
  README.md                     用例说明与运行索引
  cases.json                    实际用例与覆盖，不提前伪造
  <运行编号>/
    README.md                   中文实测报告
    result.json                 逐项机器结果
    manifest.json               来源、编码版本、大小与 SHA-256
    evidence/                   去重后的轻量证据（无 PNG）
```

## 状态五态

`通过`、`失败`、`受阻`、`未验证`、`待目视`。"待验"统一写作"未验证"。
参考包比较通过不得写成当前代码回归通过；缺证据或未目视时不得整体通过。

## 每份实测报告必须写清

1. 目的、对拍编号、参考与候选、与上一轮的关系。
2. 源码和差异指纹、配置、输入、实际依赖及设备。
3. 完整命令、工作目录、tmux 会话名、起止时间、耗时、退出码与输出目录。
4. 实际 seed、attempt、难度、分支、`rrt_fallback_count`、worker、GPU 及执行顺序。
5. 逐用例结果与实测帧数、事件数、字段数、差异数。
6. 首个分歧、必要上下文、原因是否确认、失败或受阻及未覆盖项。
7. 证据索引、实际文件数与体积、完整产物位置、重跑与离线比较命令。

未运行不填预期数字；不能从候选配置或打印的成功消息推断数据一致。

## 轻量证据的能力边界

指纹能判断内容是否相同并定位到字段／记录，但**不能还原画面或计算像素差幅度**；
需要展开时按冻结命令重跑，或从 `artifacts/` 按散列取回原图。轻量包不是完整 HDF5 备份。
