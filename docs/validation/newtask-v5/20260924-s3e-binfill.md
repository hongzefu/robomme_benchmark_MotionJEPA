## 二、`_spawn_cubes_xhard` 设计

xhard 的随机调用顺序：按钮 rand(2) → 孔板 rand×3 → 配额（`color_pool=randperm(3)`、`put_in_color`、目标分配、`total_spawn`、余量分配，**逐字不动**）→ `spawn_order=randperm(12)`（不动）→ **槽位几何** → **配色重排（追加）**。

1. **槽位（只做几何）**：对 k=0..11 做与 `spawn_random_cube` 拒绝循环逐次相同的抽样（每 trial 依次 u1、u2、yaw；区域按方块半边长内缩；候选方块按 `min_gap=0.02` 外扩后与障碍做 SAT 相交；`max_trials=256`，与 V4 调用点一致）。障碍＝按钮 OBB（预制三元组）+ 孔板四条边 + **已放槽位的 `cube_obb2d_exact` 精确三元组**（替代 V4 的「actor 走 `get_actor_obb` → 退化线段」路径）。接受的位姿经 `self._spec.value("layout.slots.<k>", [x, y, yaw])` 注入。放不下直接抛 `SceneGenerationError`（BinFill 模块内是真类，未被遮蔽）。
   - 外扩方形包含「方形 ⊕ 半径 0.02 圆盘」，所以相交判定通过 ⇒ 精确欧氏间距 > 2 cm：名义间距真正生效。
2. **配色（位置不动）**：初始配色＝槽位 k 放 `cube_tasks[k]`（即 V4「按 spawn_order 生成」的语义，不需重排的局与 V4 同义）。最大同色连通团 > `max_component` 时循环：`perm = torch.randperm(12)`，候选配色＝`cube_tasks[perm[k]]`（每次都是对初始列表的独立均匀排列，不累积），团更小则记为最优；满足上限即停，最多 `max_redraws` 次，失败取团最小的一次（并列取最早）。
   - N18：循环里不调用 `recorder.value`；循环结束后 `record("objects.color_redraws")`、`record("objects.color_mix_fallback")`、`record("objects.color_mix_max_component")`（后者是我加的证据键），然后**只调用一次** `value("objects.slot_assignment", ["red_3", "green_0", ...])`（身份串 `<颜色>_<色内序号>`，与 actor 名 `cube_<身份>` 对应）。
3. **建 actor**：按槽位顺序 `spawn_random_cube(color, name_prefix=f"cube_{name}_{idx}", fixed_xy=[x, y], fixed_yaw=yaw, include_existing=False, avoid=None, generator=None)`，不抽随机数；`self._spec.record("layout.cubes.<身份>", [x, y, yaw])`（路径与 V4 相同，改为 record）；`all_cubes` 与各色列表按槽位顺序追加（与 V4「列表顺序＝生成顺序」同义，`_initialize_episode` 取每色列表前 target 块的语义不变）。之后原有的 `spawn_requested/actual` 记录与缺块检查照旧执行（恒 12/12）。

**N17 回放复核**（冻结值不经拒绝循环）：
- 每个槽位冻结值：中心须在内缩区域内、外扩 0.02 后不与按钮／孔板／已放槽位相交，否则 `EpisodeSpecError`；
- `slot_assignment` 冻结值：必须恰是本局方块身份的一个排列；其最大同色团 ≤ max(T, 本次实算的最优团)，否则 `EpisodeSpecError`（兜底局放行不劣于实算最优的冻结值）。
- 导出模式下这些检查恒通过（同一判据）。

## 六、与计划不符之处／实现取舍

1. 计划 S3e 行写「新增 … 与 `cube_obstacle_obb`」。我理解为「方块障碍改用精确 OBB」这件事，按 2.12 表直接用 S2a 的 `cube_obb2d_exact` 实现，**没有新增名为 `cube_obstacle_obb` 的 decision 键或函数**（障碍框是缺陷修复、不是可调参数）。若主会话本意是一个 decision 键（如开关），需补。
2. 计划 S2 行把 `max_same_color_component` 列在 `utils/xhard.py`；为免与其他 S3 分支在共享文件上冲突，我放在 `BinFill.py` 模块级 `_max_same_color_component`（只有 BinFill 用）。合并时若想挪到 `utils/xhard.py`，函数体可原样搬。
3. 连通判据用 **≤ 0.09**（任务说明原话「中心距 ≤0.09 连通」）；规划期原型 `analyze_lib.stats_for` 用的是 `<`。两者只差测度为零的边界。
4. 重排每次是对**初始列表**做一次独立 `randperm(12)`（不在上一次结果上累积），并列时取最早的一次作兜底最优。
5. 槽位放不下时立即抛 `SceneGenerationError`；V4 是「记日志、继续放后面的块、最后按缺块抛错」。结果同为本局失败，只是失败局少抽几次随机数。
6. 新增证据键 `objects.color_mix_max_component`（record）。
7. 旧注入通道（`episode_spec` 非 None）在 xhard 下仍走原循环（按规格固定位姿建块，不经槽位与配色），与 V4 相同。
8. 离线复刻（测试用）只复刻到 spawn_order 为止，方块部分跑的是真实方法；它与真实环境的一致性由 4.3 的 5/5 逐位对上佐证，不代表对复刻本身做了全面验证（N16）。
9. `_resolve_sampling_config` 的 color_mix 校验在原三档实例化时也会跑一次（纯判定、默认值必过、不抽随机数），见第三节。

## 八、给合并者的注意事项

- 新 API（均在 `robomme.robomme_env.BinFill` 模块）：
  - `_max_same_color_component(xy, labels, link) -> int`：`xy (n,2)`、`labels` 长度 n、同色且中心距 ≤ link 相连；
  - `_board_strips_obb2d(board_actor) -> list[(c, A, h)]`：孔板四条边的预制障碍；
  - `BinFill._spawn_cubes_xhard(self, cube_tasks, avoid, cubes_cfg, min_gap, generator)`：只在 `spec is None and difficulty == "xhard"` 调用；`avoid` 只接受预制三元组与孔板 actor，其余类型抛 `TypeError`。
- 新规格路径（xhard）：value 点 `layout.slots.<k>`（k=0..11，`[x, y, yaw]`）、`objects.slot_assignment`（12 个 `<颜色>_<序号>`）；record 点 `objects.color_redraws`、`objects.color_mix_fallback`、`objects.color_mix_max_component`、`layout.cubes.<颜色>_<序号>`（V4 中是 value，现为 record）。消费 `layout.cubes` 作为 value 点统计的工具（如 value_points 计数）在 V5 BinFill 上会看到数目变化（12 个 `layout.cubes` value → 12 个 `layout.slots` value + 1 个 `slot_assignment`）。
- decision：`configs.xhard.color_mix` 进入申报形状；S4 重导 `scripts/configs/newtask-v5/sampling_config.json` 时会带上。V4 快照在 V5 代码上被形状检查拒绝（预期）。
- `test_v4_xhard_binfill.py` 两处断言改成 V5 语义（多一个 `color_mix` 键）。
