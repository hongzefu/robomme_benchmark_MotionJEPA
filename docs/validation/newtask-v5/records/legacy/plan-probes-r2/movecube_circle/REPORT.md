## 二、副本校验证据

- `REPLICATION_V4 match=10/10`（seed 5400000…5400900，maxerr ≤ 3.6e-9，way_idx、obj_sample 全部一致）。
- ⚠ 执行段方块对演示段方块的障碍，必须按**满尺寸方块 OBB** 建模才能 10/10；旧探针（`plan-probes/movecube/mc_layout.py`）用的「trimesh 退化线段」模型在 5400500 上与真实 spec 不符（9/10）。V5 规定 `include_existing=False`，这个障碍被整个移除，所以对 V5 统计没有影响。只是旧探针 `exec_fail.py` 里「trimesh」那几行数字不能当真实值引用。
- 补丁后的真模拟器 reset 与副本逐值对拍 **6/6 AGREE**（1000442、1000446、5400000、5400500、2000000、2000001）：布局 maxerr ≤ 1.6e-9，way 一致，各取值点拒绝计数与副本完全相同。

## 三、离线统计（5000 局，口径 A = 计划 2.9 的杆段 root−0.075u…root+0.025u）

| R | 布局失败 | 每局重抽 均值 / p50 / p99 / 最大 | 每局随机调用 均值 / p99 / 最大 | 最终布局禁区违规 | 耗尽概率估计（Σ rate^128） |
|---|---|---|---|---|---|
| 0.04 | 0/5000 | 0.83 / 0 / 5 / 8 | 33.3 / 51 / 71 | 0 | 5e-59 |
| **0.05** | **0/5000** | **1.79 / 1 / 8 / 15** | **35.0 / 54 / 72** | **0** | **7e-34** |
| 0.06 | 0/5000 | 4.72 / 4 / 20 / 35 | 40.8 / 75 / 117 | 0 | 6e-14 |

对照：不设禁区、bias 0 时每局随机调用 32.7 / 55 / 79。R=0.05 下每局重抽次数分布：0:1381、1:1321、2:958、3:588、4:345、5:177、6:100、7:62、8:24、9:19、10:14、12:4、13:3、14:2、15:2。

| 取值点 | 原始抽样落进圆（实测） | 解析值 | 中心判据检查口径（实测） | 单局最多重抽 |
|---|---|---|---|---|
| goal 演示段 | 16.1% | 16.2% | 16.1% | 4 |
| goal 执行段 | 55.1% | 54.5% | 55.1% | 15 |
| 方块候选 演示段 | 19.7% | 19.6% | 15.3% | 5 |

| 方块最终 执行段 | 6.5% | — | 6.5% | 5 |
| 杆（计划口径） | 0 | ≈0 | 0（杆段离圆心最近 0.0778） | 0 |

「检查口径」只数先通过 |c−g|>0.1 判据、再被圆拒掉的那部分；执行段 goal 本身就挤在中心附近，所以候选到这一步前大多已被 goal 距离判据拒掉，中心判据的实际拒绝率只有 3.5%。

**R=0.04 / 0.06 参考拒绝率**：goal 演示段 10.1% / 22.9%，goal 执行段 35.1% / 78.8%，方块候选原始落圆 12.5% / 28.5%，方块最终 4.4% / 11.0%（演示段）。

**不设禁区时（bias 0）最终布局的落圆比例（R=0.05）**：goal 演示段 16.2%、执行段 54.3%，方块演示段 13.0%、执行段 4.1%。70.2% 的局至少有一个物体中心落进圆（计划口径杆不算）。新规则把这一比例压到 0。

## 四、⚠ 杆的几何口径与计划不符（需要用户定）

模拟器实测（`build_peg`，seed 5400000 读 link 位姿）：head link 中心就在 root，tail link 中心在 root − 0.1·u（两中心间距实测 0.100），两段的 visual 半长都是 0.05。所以**杆的物理/视觉范围是 root−0.15u … root+0.05u（全长 0.20）**，不是计划写的 root−0.075u … root+0.025u（0.10）。

- 按计划口径，杆规则**永远不会触发**（5000×2 根杆里离圆心最近的是 0.0778）。但真实杆身会伸进中心：不设禁区时每段约 **3.8%** 的杆身进入 5 cm 圆，比如 seed 2000000 演示段杆身离圆心只有 1.39 cm。本次 V5 演示 5400600 的执行段杆身离圆心 2.1 cm，演示 5400001 的执行段也只有 7.9 cm。
- 若改用实测口径 B（−0.15, 0.05）：杆每次抽样拒绝率 3.8%（R=0.04 时 2.3%，R=0.06 时 5.6%）；整体仍然 0/5000 失败，每局重抽均值 1.86、p99 8、最大 15，禁区违规 0。其他取值点与口径 A 几乎一样（杆多重抽一次，会让后面的随机流整体后移）。
- 建议：用户原意是「三个物体尽可能都不出现在中心」，应把实施口径改成实测杆段 (−0.15u, +0.05u)，代价几乎为零。这是实施口径问题，交用户确认，本探针不自行定。

## 五、本机演示（进程内补丁，R=0.05，计划口径杆段）

⚠ **way 的来源**：`gym.make` 和 `reset()` 各调用一次 `_initialize_episode`，演示实际用的是 `initializations.1.way_idx`（第二次 `randint(3)`），不是 `initializations.0`。已用 4 个 seed 的真模拟器 spec 加视频字幕核实。demo 日志 `demo.log`、`demo2.log`、`ctrl.log` 里打印的 way 是旧口径（init0），以 `demo_table.out` 重新标注的为准。

seed：v4-01 的 MoveCube 10 个（5400000…5400900 步长 100），加上 5400001…5400014 中的 14 个，共 24 个。

| 组 | 成功 | peg_push | gripper_push | grasp_putdown | 成功局步数（timestep_count）最小 / 均值 / 最大 |
|---|---|---|---|---|---|
| **V5 R=0.05** | **19/24** | 5/8 | 6/8 | 8/8 | 246 / 429 / 942 |
| 对照 R=0（同补丁、不设禁区） | 22/24 | 3/4 | 7/8 | 12/12 | 253 / 410 / 942 |

V5 失败分类（均为任务类 `failure_class=task`，没有一例是生成或 reset 失败）：
- `PlannerExhausted`（screw 三次与 RRTStar 三次均失败），peg_push：5400200、5400008，复跑仍然失败（可复现）；
- `DatasetGenerationError: 跑完整个 task_list 仍未成功`：peg_push 5400001（钩完方块没到 goal），gripper_push 5400500、5400005（推到 goal 旁边，差一点没到位，见 `fail_frames/`）。
- 5400500 零重抽，与对照组布局逐位相同，对照组同样失败，说明与禁区无关。

**同一布局的演示不确定性**：零重抽的 7 个 seed 两组布局逐位相同，其中 5400400 在 V5 首跑成功、对照组失败、V5 复跑（`rerun.log`）又失败。可见同一布局的演示结果本身会抖动（本机当时还有 P1/P3～P6 探针并发）。19/24 与 22/24 的差距（3 局）在这种抖动和样本量下**不显著**（Fisher 精确检验远未到 0.05），peg_push 在两组里都是最弱的一种 way。

**执行段方块生成**：reset seed 1000442、1000446 均 OK（V4 下这两个 seed 因执行段方块被演示段方块挡死而失败），并与副本逐值一致 → `exec_spawn_ok=2/2`。1000446 的执行段 goal 被重抽了 6 次。

## 六、对 R=0.05 是否合适的判断

- **生成侧完全合适**：5000 局零失败、零违规；最坏的取值点（执行段 goal，55%）在 128 次预算下耗尽概率约 1e-33；每局平均只多抽约 2.4 个随机数。R=0.06 仍然可行（执行段 goal 拒绝 79%，耗尽 5e-14），但每局重抽均值涨到 4.7，而且执行段 goal 被压进半宽 0.06 框的四角；R=0.04 的空地在画面上不够明显。维持 0.05。
- **演示侧**：没有看到禁区带来的系统性退化（19/24 对 22/24，差距落在抖动和样本量之内）；peg_push 的 PlannerExhausted 两例可复现，值得在 S3c 用更大样本盯一下。
- **需要改的实施口径**：杆段应按实测几何 (−0.15, 0.05)，否则「杆不进中心」这条规则形同虚设（第四节）。

## 七、盲区

1. 演示样本仅 24+24 局，统计功效低；同布局演示有抖动，而且跑的时候本机有其他探针并发。
2. 离线副本只校验了「无规则 + bias 0.5」（10/10）和「新规则」的 6 次真 reset；5000 局统计本身没有逐局上真模拟器。
3. 方块候选的「128 次」上限在实现上与原有 `max_cube_spawn_trials=128` 循环共用，两者谁先耗尽都算失败；本探针两处均未触发。goal 的中心拒绝发生在 `spawn_random_target` 的 256 次循环内，另有独立的 128 次计数，先到先抛。
4. 杆的判据只看轴线（不含 0.01 的截面半宽），按中心判，符合用户口径；按轮廓判会更严。
5. 补丁中 corner_bias 是置 0 而非删键，spec 里仍会记录 `layout.*.corner_bias=0.0`；这与实施后「删干净」的 spec 字段不同，但不影响随机流。
