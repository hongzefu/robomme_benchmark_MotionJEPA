## 2. N11 根因定位（用户「n11 a」：先定位再修）

审查证据 `artifacts/audit/v6-semantic-vs-native-82e3d92/verify/crosscut-language-03/xhard4_ep3_boundaries.txt`：交换窗口 `[205,255]…[755,805]`（12 段各 50 步），录像侧 static 边界 163、222、276、…、762（间隔 54），执行段 816。机制：交换段 static 任务的内部完成判定 `static_check(static_steps=50)` 从**内部**任务切换起计 50 步；演示 wrapper 对每个演示任务依次执行 `solve`，等待解法 `_solve_hold_obj_xhard(static_steps=50)` 从**录像侧**切换（上一段 solve 结束）起再等 50 步并多消耗约 4 步；录像侧只在每段 solve 结束调用 `evaluate(solve_complete_eval=True)` 时采纳内部索引（`allow_subgoal_change_this_timestep` 只在此为真）。两条时钟每段漂 4 步（17、21、25…），当累计漂移超过一段长度（k≥9）时，某个内部 static 任务在两次采纳之间整段完成，边界被吞：ep3 在 e_8=654（内部索引 9）与 e_9=708（内部索引 11）之间跳过第 10 段；ep0 初始偏移更小、12 段内未越界，故间歇。修法：新四档第 k 段的 func 与 solve 都以 `swap_schedule[k][3]` 为绝对终点，漂移不再累计。判定行 `VR_BOUNDARY` 在回传后按「static 边界数 = 交换数 + 1」逐局核验。
