## v3历史还原命令与服务保留

以下为实际接口，已有目录和运行服务不重复覆盖或启动。生成器拒绝覆盖`catalog.json`／`media-private.json`；如需另建版本，应先选一个不存在的目录再显式传`--out`，不重跑生成轨迹：

```bash
UV_CACHE_DIR="$PWD/artifacts/cache/uv" uv run --no-sync python \
  -m scripts.parity.v6_site_catalog --out artifacts/newtask-v6/site-v3
```

上面是v3目录生成接口记录，当前目录已存在，直接重执行会被拒绝；生成器只生成目录JSON，JPEG预览为本轮另行完成的CPU处理产物，不声称该单条命令会生成预览。实际服务入口：

```bash
UV_CACHE_DIR="$PWD/artifacts/cache/uv" PYTHONUNBUFFERED=1 uv run --no-sync python \
  -m scripts.parity.v6_site --host 0.0.0.0 --port 8060 \
  --site-dir artifacts/newtask-v6/site-v3
```

该命令由 `artifacts/newtask-v6/site-v3/launch.sh` 在独立tmux会话`v6-gradient-site-8060`执行，使用pipefail、PYTHONUNBUFFERED、tee落盘，服务结束时记`EXIT_CODE`。本报告不复制sh或yaml到docs。服务持续运行时日志没有最终退出码是预期，不能写成“服务已退出0”。

查看会话使用`tmux has-session -t '=v6-gradient-site-8060'`或`tmux attach -t v6-gradient-site-8060`，后者用Ctrl-b d脱开。按当前要求保留网站会话与产物，不自动停止；未来若明确要求停止，只能精确操作这一会话，禁止全局tmux清理，也不触碰S3或集群占位作业。
