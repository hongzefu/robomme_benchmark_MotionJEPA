# MoveCube xhard 抓杆可达性实测报告（探针 B）

## 结论先行
- **抓不抓得起只取决于抓取点离基座的水平距离，与 yaw 无关。** 抓取点是 peg_tail 中心 = root − 0.10·u，基座在 (-0.615, 0)。
  12276 次试验中：
  - 距离 d ∈ [0.268, 0.801] m 的全部成功，0 例失败；
  - d < 0.233 或 d > 0.854 的全部失败；
  - [0.233, 0.268) 与 (0.801, 0.854] 是过渡带。
- **xhard 翻转归约在全部 12 个 yaw 下都能正常工作**，没有出现"因为朝向而抓不起"的格子。各 yaw 可达面积不同，完全是因为抓取点相对根偏移了 0.10·u 造成的。
- **当前杆根框在 12 个 yaw 下全部可抓**：x∈[-0.05, 0.05]、y∈±0.2±0.05，共 50 格，逐 yaw 都是 50/50，交集也是 50/50。
- **建议边界（各留约 1 cm 余量）：**
  - 抓取点离基座距离 ∈ [0.28, 0.79] m；
  - 换成对杆根的约束（yaw 连续任意）：|root − 基座| ∈ [0.38, 0.69] m；
  - 若用以 (0,0) 为圆心的圆：
    - 杆根半径 ≤ 0.075 m 时 yaw 连续任意都安全（12 个离散 yaw 实测到 0.10）；
    - 抓取点半径 ≤ 0.18 m 安全；
    - 杆身中点半径 ≤ 0.12 m 安全（连续 yaw 推算；离散实测 0.15）。

## 方法
- 脚本：`probe.py`（每个 worker 一个环境）、`run_grid.sh`（16 个 worker 并行）、`analyze.py`（汇总与出图）。
- 环境：`gym.make("MoveCube", difficulty="xhard", control_mode="pd_joint_pos", reward_mode="dense", seed=0)`，reset 一次，确认 `_xhard_peg_yaw_reduction=True`。
- obs_mode 用 `state`。随机 60 组与原值 `rgb+depth+segmentation` 对比：两边都是 42/60 成功，ok/err/flipped 逐条相同，抬升后 z 的差为 0，速度快约 8 倍。
- 规划器：`FailAwarePandaArmMotionPlanningSolver`（参数同 DemonstrationWrapper），并按 DemonstrationWrapper 包上重试：screw 1 次，失败后 RRT* 最多 3 次，全部失败记 `PlanExhausted`。
- 干扰物：cube/cube_2 挪到 (10,10,1)，goal_site/goal_site_2 挪到 (10,12,1) 和 (10,14,1)。
- 每次试验：
  1. `agent.reset(初始 qpos)`；
  2. 演示段的杆 `set_pose(root, yaw)`，z 与原生成一致（为 0）；四元数与 `_load_scene` 同算法，速度清零；
  3. `_peg_grasp_flipped=False`；
  4. 调用 `grasp_and_lift_peg_side(env, planner, env.grasp_target)`。
- 抓取目标：`env.grasp_target` 实测为 `peg_tail`（evaluate 里 obj_flag 写死 -1）。
- 成功判据：无异常，且 peg_tail 的 z > 0.1，且 `agent.is_grasping(peg_tail)` 为真。
- 网格：杆根 x∈[-0.40, 0.35]、y∈[-0.40, 0.40]，步长 0.025（31×33=1023 格），yaw 0～330° 每 30° 一档，共 12276 次。没有先粗扫，直接用细网格。

## 耗时
- 16 个 worker 墙钟约 16.5 分钟（最慢 worker 991 s）。
- 单次试验累计 14128 s：成功约 0.1～0.3 s，失败约 1～3 s（主要花在 RRT* 重试）。

## 杆身几何（用各子 link 的实际 pose 和形状实测）
- peg_head 以根为中心，t∈[-0.05, 0.05]；peg_tail 中心在 t=-0.10，t∈[-0.15, -0.05]。
- 两段合起来是 t∈[-0.15, +0.05]，与 `_peg_axis_extent` 一致：从根沿 -u 伸 0.15、沿 +u 伸 0.05。
- 例：root=(0.1, -0.2)、yaw=90° 时，端点为 (0.1, -0.35) 和 (0.1, -0.15)。
- 杆身中点 = root − 0.05·u；抓取点（peg_tail 中心）= root − 0.10·u。

- **yaw 为什么影响面积：** yaw=0 时抓取点比根更靠近基座 0.1，远端能多伸 0.1、近端先失败；yaw=180 时正相反。面积与内切圆关于 yaw=0/180 对称。
- **翻转归约的作用范围：**
  - yaw=0 时从不触发；30°/330° 约 3%；60°/300° 约 23%；90°/270° 约 61%；120°/240° 约 96%；150～210° 100%。
  - 也就是杆的 -u 朝基座一侧、夹爪 x 轴与"基座→抓取点"方位差超过 90° 时触发。
  - 触发后仍然能抓起：触发样本的成功率 68%，未触发的 78%。这个差异来自抓取点位置分布，不是翻转本身的问题。
- 抓取点离基座的最大成功距离：各 yaw 都在 0.838～0.854 之间，一致。

## 失败类别（共 3341 例）
- **PlanExhausted：2543 例。** screw 和 3 次 RRT* 全部失败。其中近端（d<0.5）281 例，远端 2262 例。
- **NotLifted：738 例。** 没有异常，但杆没被抬起，几乎都在远端过渡带（721 例）。规划器报了成功，但末端够不到或擦边没夹住。
- **NotGrasping：60 例。** 杆离开了桌面但不在夹爪里，只出现在远端、yaw 150～210°。
- 另有 396 例成功依赖 screw 失败后的 RRT* 兜底。
