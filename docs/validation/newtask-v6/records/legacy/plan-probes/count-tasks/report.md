> 2026-09-25，只读调查，代码锚点 HEAD da77662。由主会话代 subagent 落盘。脚本与输出在本目录：mc_lib.py、run_mc.py、run_mc2.py、verify_sat.py、binfill_color.py、camera_reach.py、frames_h5.py、frames_analyze.py、peek_h5.py 及各 *.log/*.json、frames/。

## 〇、结论先行

1. PickHighlight 的上限在 reset（物理）：现有框下 N=9 成功率 93.4%，N=10 只有 71.8%；现 xhard spawn [8,10] 已骑在上限上（V5 S6 抽签 10/12 吻合）。不放大框加不出新档。只把 y 半宽放到 0.30（x 不动）、预算提到 1024 后，N≤14 时 ≥99.8%，N=16 为 91.3%。
2. PickXtimes 的上限在时长：一次抓放单局均值最坏 243 帧、固定开销最坏 122 帧；5000 帧内重复 20 次约 4982 帧，余量不到 1%。建议次数上限 18（最坏 4496 帧）。
3. SwingXtimes 时长不卡（每轮 77 帧，最坏 49 轮才触线），卡的是文本：子目标序数用本文件局部表，只到 tenth。BinFill 两类上限都有余量。
4. 相机视野不构成约束，可达性才是：Pick/Swing 框远角离基座已有 0.780 m，V5 演示验证过的最远点 0.765 m，InsertPeg 在 ≥0.81 m 失败过。框只能往 y 向放大，x 不动。
5. 离线复刻与仓库 `_obb2d_intersect` 做了 20000 例对照，0 例不一致（`SAT_MATCH mismatch=0/20000`）。现值点与 V5 已知数对得上：BinFill 0 失败、PickXtimes 0 失败、Swing 圆盘失败约 3%。

## 五、文本与数词

`num2words` 与 `_ORDINALS` 覆盖 1～20，超出目标文本变阿拉伯数字。BinFill 每色最多 13 不越界；PickXtimes 最多 18 不越界；SwingXtimes 子目标用本文件局部表 `ordinals` 只到 tenth，11～20 轮写成 "11th" 这类数字、21 轮起错拼 "21th"；PickHighlight 目标无数字。干扰色不进文本。

## 六、风险

演示成功率未测（次数增加后抓放失败累积：单次 1% 失败连续 18 次全成功约 83%）；PickXtimes +3 只剩 10% 帧数余量而 `fail_safe_limit` 属冻结录像器；放大 y 后远角（0.749 / 0.758 m）在已验证范围内但未做本框演示；离线复刻用 numpy 随机数只做统计；PickHighlight 现 xhard 抽签失败率约 12%（N=10 时 28%）；SwingXtimes 圆盘约 3% 失败原样带进新档。

## 七、待决项（调查方建议）

1. 新档名与挂法：沿用 `decision` 下按档名放行的子树机制，档名由用户定。
2. PickXtimes / SwingXtimes 梯度维度：A 只加次数 / B 只加干扰块 / C 联动。建议 C。
3. 干扰超过 3 块时的颜色：A 黄/青/品红循环 / B 扩充 `DISTRACTOR_COLORS` / C 非目标原色多放几块。建议 A。
4. PickHighlight 干扰数抽法：A 沿用 spawn、pick 独立抽且 `spawn_lo ≥ pick_hi` / B 干扰数单独抽，spawn = pick + 干扰。建议 B。
5. PickHighlight y 半宽 0.20→0.30、预算 256→1024；现 xhard 是否一起改（会平移产物）。建议新档必改，xhard 由用户定。
6. BinFill +2 提预算、+3 y 半宽 0.32；备选 +3 只到 17 块不放大框（95.8%）。建议前者。
7. SwingXtimes 子目标序数：A 扩到 twentieth / B 保留 "11th"。建议 A。
8. PickXtimes 次数上限：A 18 / B 20（需放宽冻结的 5000 帧上限）。建议 A。
9. 新档次数区间能否与 xhard 重叠（靠均值与干扰数递增）：建议允许。
