## 〇、结论先行

1. **现状失败的根因不是「3 个最近」，而是可行图太稀疏。** 在 0.12 m 间距、5 mm 余量、按钮作障碍的条件下，每个槽位平均只能和 **1.54** 个槽位交换（15 对里平均只有 4.61 对可行）。不可行对中，撞其他方块的占 54%，只因按钮不可行的占 16%（600 局抽查）。**41.0% 的布局存在「孤立槽位」**（这个位置上的方块和谁都换不了）。现状失败率 41.03% 与孤立槽位率 41.02% **逐局重合**：只要 n_swaps ≥ 方块数，k%N 轮流迟早会让孤立块当发起者。「3 个最近」这条限制几乎从不起作用：可行度本来就 ≤ 3，把它去掉（S2）的成功率、路径长度与现状完全相同。
2. **现状在跨局、按方块编号统计时已经均匀**（参与次数卡方 p = 0.93）。**不均匀出现在单局之内，并且和几何相关**：单局内各块参与次数的极差多为 2～3（极差 ≤ 1 的只占 14.7%）；参与率随所在槽位的可行度上升（可行度 1 的槽位是均值的 0.970 倍，可行度 4 的是 1.098 倍），离按钮 12 cm 以内的块是 0.976 倍；每局平均还有 0.99 次「刚换完又原对换回」。
3. **推荐 S5「均衡贪心 + 整条重试」。** 每次在全部可行对里挑「两块已参与次数之和最小」的一对，平局随机；整条序列不满足「极差 ≤ 1」就换随机数重排，最多 20 次。结果：N=6 时 **96.7% 的局做到极差 ≤ 1，其余为 2**；参与率与可行度、按钮距离**无关**（0.998～1.012）；没有紧邻换回；reset 成功率不下降（仍是 58.97%，只在有孤立槽位时失败）；平均重试 1.96 次，因为可行性矩阵已缓存，重试几乎不花时间。
4. **更难档的真正瓶颈是 reset 成功率，不是帧数。** 区域固定时，reset 规划成功率（方块摆得下且没有孤立槽位）：N=6 0.589 → N=7 0.526 → N=8 0.400 → N=9 0.226 → N=10 0.062。帧数方面，环境控制步 ≈ 440 + 50·n_swaps + 140·repeats（规划器波动最多 +300），离 5000 的上限还很远。
5. **三档建议**（详见第三节）：X1 = 7 块、换 12～16 次、重拿 6～8 次；X2 = 8 块、换 16～20 次、重拿 8～10 次；X3 = 8 块、换 20～24 次、重拿 10～12 次。控制步最坏约 2.4k / 3.0k / 3.6k，都低于 5000。N=8 时 reset 成功率约 0.38，**抽签上限需要从 30 提到 ≥ 60**（上限 30 时凑不满 10 条的概率是 23%，上限 60 时是 7e-5）。想上 9～10 块，必须扩大区域或改余量，二者都会触及冻结口径 L51/L49。

### 1.2 xhard 随机流顺序（xhard 专属，原三档不经过）

`__init__`：`randint(4,7)` 决定 num_repeats → `randint(8,13)` 决定 n_swaps → `_load_scene`：`build_button` 的 `rand(2)` → `_load_cubes_xhard`：颜色 `rand(3)` → 逐块每次 trial 抽 3 个 `rand(1)`（x, y, yaw）；判据依次是按钮 OBB（半边 0.05625）、已放方块的精确 OBB（新块外扩 min_gap = hs）、0.12 m 最小中心距 → 目标 `randint(0,6)` → `randperm(5)` → **追加** `rand(n_swaps)`（`objects.swap_partner_u`）→ `_plan_swaps_xhard` 规划，这一步不再抽随机数。

### 1.3 可行性判定入口

`_XhardSlotSweepFeasibility.feasible(slot_a, slot_b)`，底层是 `utils/bin_collision.py::check_swap_sweep_prefiltered`。两个移动块与其余槽位都用 `cube_shape_specs(0.02 + 0.005)` 的放大形状；按钮底座 `button_base_state(scale=1.5)` 作为静止旁观物；结果按无序槽位对缓存。槽位集合整局不变，只是占用者在槽位之间置换，所以一张 N×N 的可行矩阵就完全描述了整局的约束。运行时守卫是 `_check_swap_sweep_from_actual`。

### 1.4 蒙特卡洛：现状在对象层面的分布（`study.py` / `analyze.py`，10000 局，seed 7100000～7109999，输出 `study_n6.txt`）

- 摆放成功 9999/10000；规划成功 **58.97%**，失败均匀分布在第 0～5 次交换。
- 每块参与次数（跨局累计，按 bin 编号）：[19606, 19728, 19628, 19620, 19507, 19667]，卡方 = 1.4，p = 0.93，**均匀**；发起者卡方 p = 0.999，搭档卡方 p = 0.87。
- 按方块对统计（15 格）：卡方 = 60.2，p = 1e-7，**不均匀**。但所有方案都不均匀（S3 p = 2e-8，S4 p = 2e-7），原因在几何：生成顺序会影响相对位置，而可行图平均只有 4.6 条边。**「每对等概率」在这个几何下做不到，也不应当作目标。**
- 单局之内：参与次数极差分布 {0: 161, 1: 704, 2: 2801, 3: 1659, 4: 494, 5: 73, 6: 5}（成功局共 5897 局），极差 ≤ 1 的只占 14.7%。
- 与几何相关（碰撞检测带来的偏差）：参与率随初始槽位可行度变化，可行度 1 → 0.970，2 → 1.011，3 → 1.043，4 → 1.098；按钮 12 cm 以内的块 0.976，其余 1.001。
- 布局层面的选择偏差：被接受的局里「最近块到按钮中心」的平均距离是 0.1419 m，全部局是 0.1374 m。41% 的拒绝会系统性地淘汰「有块靠近按钮」的布局，任何在对象层面做均衡的方案都去不掉这一层，只有改几何才行（见第三节）。
- 路径：单段均值 0.173 m，p95 0.267 m，最大 0.454 m；目标块被换次数均值 3.65，P(≤2) = 5.9%；每局紧邻换回 0.99 次。

### 2.2 推荐算法（S5，规格写法沿用 `actions.swap_pairs.<k>`）

```
输入：槽位可行矩阵 M（N×N，源码 _XhardSlotSweepFeasibility 口径），n_swaps
if M 有全零行: raise SceneGenerationError      # 孤立槽位 ⇒ 这块不可能参与（与现状失败条件逐局相同）
for t in 1..20:
    cnt = 0（每块参与次数）；occ/slot_of 为恒等映射；last = None
    for k in 0..n-1:
        cands = {可行无序槽位对} − {last}                 # 禁止紧邻换回
        取 score = (cnt[占用者a]+cnt[占用者b], max(二者))  最小的那些对，均匀抽一对，并用一次随机数决定谁当 initiator
        更新占用关系、cnt、last
    if max(cnt) − min(cnt) ≤ 1: 采用本序列并停止
耗尽 20 次仍不满足 ⇒ 按待决项 V6-VR-2 处理（用最后一条，极差为 2；或者判本局失败）
```

- **随机流建议**：tie-break 与重试需要的随机数个数不固定。建议在主流上**追加一次** `torch.randint(2**62)` 得到 `plan_seed`，规划在局部 `torch.Generator(plan_seed)` 上进行。这样主流的抽取次数固定，与 V5「追加 `rand(n_swaps)`」的先例同形。规格里冻结 `objects.swap_plan_seed` 与逐次的 `actions.swap_pairs.<k>`；回放时按 N17 复核「每对扫掠可行 + 极差 ≤ 1 + 没有紧邻换回」。
- **发起者**：两块的交换动作是对称的（`swap_flat_two_lane` 中两块同时移动），「发起者」只是代码里 `swap_pair{k}_idx1` 的角色。S5 用随机数决定方向。`objects.swap_initiators` 这类 k%N 轮转的字段在新规则下失去意义，要改为 record 实际序列。
- **代价**：可行矩阵一次算全。N=6 平均 78 ms（p95 162 ms），N=8 约 200 ms；现状是按需缓存，只查到过的对才算。20 次重试本身不再做几何计算。

### 3.2 帧数（`h5_frames.py` / `frames_fit.py`，v5-01 三局 h5 + s3g 本机 7 局控制步）

- **每次 swap 恰好 50 控制步 = 50 帧**（`_refresh_swap_schedule`，窗口固定）；演示帧 ≈ 255 + 50·n（三局误差 ≤ 6 帧）。
- **每次 repick**（pick + put down）≈ 125～140 帧：pick 69～81，put 52～61；第一次 pick 多约 30 帧。尾部 button 57～76 帧，加 completed 35～48 帧。非演示帧 ≈ 150 + 135·r。
- `NO RECORD`（strong reset）不进 h5：4900300 的控制步 1732 与 h5 的 1696 相差 36。录像器的 `fail_safe_limit = 5000` 按**环境控制步**（`elapsed_steps`）计算，包含 NO RECORD。
- 保守模型：**控制步 ≈ 440 + 50·n + 140·r，规划器波动最多 +300**。s3g 的 7000001 比模型多 219～280 步。
- 上限：取 r = 12，控制步 ≤ 4500（留 500 余量）时 n ≤ 47；取 r = 20（`task_goal.num2words` 只写到 twenty，超过 10 次时子目标序数退化为 "11th"）时 n ≤ 25。

### 3.3 三档建议表（区域、0.12 m、5 mm 余量、按钮障碍都不变；搭档用 S5）

| 档 | 方块数 | n_swaps | repeats | 演示帧（≈ 255+50n） | 控制步最坏（+300 波动） | reset 成功率 | 抽签上限建议 | S5 单局极差 ≤ 1 |
|---|---|---|---|---|---|---|---|---|
| xhard（冻结） | 6 | 8～12 | 4～6 | 655～855（22～28 s） | ≈ 1.9k（2.2k） | 0.59 | 30 | 96.7% |
| X1 | 7 | 12～16 | 6～8 | 855～1055（28～35 s） | ≈ 2.4k（2.7k） | 0.52 | 40 | 100% |

- 路径：N 越大路径越短（N=8 时 p95 0.22 m，最大 0.43 m），速度问题比 xhard 轻。

## 四、原版梯度（确认 VideoRepick 属于「原版有梯度」）

原版 easy / medium / hard 有三个字段随难度变化：**swap 次数**（[1,2] → [2,3] → 0）、**方块数与颜色结构**（3 块同色 → 3 块同色 → 15 块 3 色，每色 5 块）、**布局**（锚点三角/直线 → 同左 → 整片矩形）。repick 次数三档都是 [1, 3]，没有梯度。这个梯度**不单调**：hard 改成「多色杂乱、不交换」，走的是另一条路线。xhard 沿 easy→medium 的 swap 方向加难，并吸收了 hard 的整片区域。所以 VideoRepick **属于原版有梯度的任务**。更难的三档建议继续沿 xhard 的轴走（块数、swap、repick 三者一起加），不要回到 hard 的多色路线。

## 五、风险

1. 可行图很稀，均衡在少数局做不到：N=6 时 3.3%、N=8 时约 6.5% 的局在 20 次重试内只能做到极差 2。
2. 布局选择偏差（U5）在任何对象层面的方案下都存在；N=8 时 60% 的布局被拒，偏差会变大（0.131 vs 0.129 m，数值上仍然小）。
3. N=8 的 reset 成功率 0.38～0.40：抽签上限必须提高，否则 23% 的概率凑不满 10 条候选。
4. 以上全是离线几何估计；7～8 块时抓取的可达性、repick 时误碰相邻块、规划器超时都没有测。**需要在本机各跑 ≥ 4 局演示**。
5. 若把 S5 也用到 xhard，xhard 的 `actions.swap_pairs` 语义会变，需要重冻 xhard（与「原三档冻结」不冲突，但 xhard 本身是 V5 的冻结产物）。

## 六、待决项

- **V6-VR-1 「均匀」的定义**：(a) U2 单局极差 ≤ 1 + U3 与几何无关（建议）；(b) 只要 U1 跨局均匀（现状已满足，等于不改）；(c) U4 每对等概率（与全员参与冲突，不建议）。
- **V6-VR-2 均衡做不到时的兜底**：(a) 接受极差 2（S5 取最后一条，N=6 占 3.3%，建议）；(b) 判本局 SceneGenerationError 重抽（reset 成功率再降 2～4 个百分点）；(c) 把重试预算提到 100（改善很少）。
- **V6-VR-3 新搭档规则是否同时替换 xhard**：(a) 只用于 3 个新档，xhard 保持冻结；(b) xhard 也换成 S5 并重冻 v6（建议：用户原话针对的是 repick 任务整体，xhard 现状单局极差 ≤ 1 只有 14.7%）。
- **V6-VR-4 三档参数**：(a) 第三节 3.3 表（7/8/8 块，区域不动，建议）；(b) 扩区域到 x ∈ [−0.30, 0.20]、y ∈ [−0.30, 0.30]，做 7/8/9 块（reset 成功率 0.81 / 0.78 / 0.73，需先验证可达性，并推翻 L51）；(c) 其他组合。
- **V6-VR-5 抽签尝试上限**：新档从 30 提到 60（建议），还是按档分别设 40 / 60 / 60。
- **V6-VR-6 5 mm 规划余量是否保留**：余量取 0 可以让 N=8 的 reset 成功率从 0.40 升到 0.645，但运行时 D5 的余隙会变小（s3g 实测最小余隙 9.1 mm）。建议保留 5 mm。
- **V6-VR-7 随机流**：追加一次 `plan_seed`，在局部 generator 上做 tie-break 与重试（建议），还是预抽固定长度的数组。
