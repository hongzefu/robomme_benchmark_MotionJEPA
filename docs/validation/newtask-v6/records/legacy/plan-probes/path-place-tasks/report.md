## 〇、结论先行

1. 原三档有梯度的只有 4 个：PatternLock（网格 3/4/5 + 节点数）、RouteStick（段数 + 是否允许回退）、VideoPlaceButton（颜色 1/3/3、目标台 3/4/4、交换 否/否/是）、VideoPlaceOrder（颜色 1/3/3、交换 否/否/是，目标台三档都是 4）。InsertPeg、StopCube 原三档逐字同值（`config_native` / `_CONFIG_CURRENT` 三档共用，注释写明「本环境原本没有难度分档」），不落入 V6。
2. 硬约束是评估预算 1301（`scripts/evaluation.py` 的 `max_steps=1300`，只数非演示步），而非录像器 5000。PatternLock 与 RouteStick 的执行段约等于演示帧数：RouteStick 在 L ≥ 27 必然超时（模拟器实测 L=26 第 1296 步成功，L=27 第 1302 步超时）；PatternLock 5×5 不重访上限 25 已用完。放宽预算后，上限改由录像器 5000 步决定。
3. VP 两环境 xhard 分支不用 `goal_site`（初始化时沉到 z=−0.05），但它仍以半径 0.06 / 0.10 的圆占着布局，是 VPO reset 只有 48% 的主因。新档把它移出 avoid 后，3 块 4 台的 reset 成功率 VPB 81.8% → 97.5%，VPO 50.0% → 97.5%。复刻布局在 300 个 seed 上与 S3i 真实 reset 逐项相同。
