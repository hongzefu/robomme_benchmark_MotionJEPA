## 已确认事实

存在两条长时间运行的全卡监控：

| PID | 父 PID | 完整监控命令 | 启动时间（本机） |
|---|---|---|---|
| 1275035 | 972715 | `watch -n -0.1 nvidia-smi` | 2026-09-26 15:53:54 |
| 1488784 | 965042 | `watch -n 0.1 nvidia-smi` | 2026-09-26 16:30:45 |

第一条参数原文确为负的 `-0.1`，不能直接把它当作已经测定的执行频率。第二条明确请求 0.1 秒间隔；命令执行时间会进一步影响实际周期。

使用纯标准库读取 `/proc`，每 0.5 秒采样一次，共 20 次，约 10 秒。20 次均看见存活的 `nvidia-smi`，记录了 32 个不同子进程 PID，命令均为无筛选参数的 `nvidia-smi`。父链全部归入上述两条 watch，例如：

- `2143644 nvidia-smi → 2143643 sh → 2143642 watch → 1275035 watch → 972715 bash`
- `2143727 nvidia-smi → 2143726 sh → 2143725 watch → 1488784 watch → 965042 bash`

没有发现 `dcgm`、`nvtop`、`collectd`、`telegraf` 命名的监控进程；该命名检查不等价于穷尽所有 Python/C 程序内部 NVML 调用。

基线 `v1/base/run_config.json` 开始于 18:10 UTC（本地 14:10），耗时 2994.218 秒，约本地 15:00 结束；两条 watch 均在基线结束后、当前 S3 开始前启动。因此它们是满足时间先后条件的环境变化，而不是同时存在于已测快速基线中的已知因素。

驱动 `/proc/driver/nvidia/version` 是 570.211.01；两卡 GPU Firmware 也均为 570.211.01。`params` 显示 `EnableGpuFirmware: 18`、`EnableGpuFirmwareLogs: 2`、`RegistryDwords: ""`、`RegistryDwordsPerDevice: ""`。这些数值只作原始证据，未从中推断异常。`warnings` 只有说明文件，没有专门警告条目；内核日志并未因此被证明无异常。

## 判断边界

全量 `nvidia-smi` 会查询两张卡；两条高频查询与主调查发现的两卡同时进入 NVIDIA rwlock 等待，在机制方向与时间先后上相容。但本次没有做停止／降低查询频率的对照，不能把相关性直接认定为八倍变慢的因果。监控属于用户已有工作现场，本代理没有干预。

复核命令：`ps -p 1275035,1488784 -o pid,ppid,lstart,etimes,comm`；分别读取 `/proc/<PID>/cmdline`；读取 `/proc/driver/nvidia/{version,params,registry}` 和 `gpus/*/information`。标准库采样经 `UV_CACHE_DIR=<仓库>/artifacts/cache/uv uv run --no-sync python` 运行，退出码 0，仅输出内存收集的相关进程命令及父链；未读取一般进程的完整命令或环境，未写入主线输出。
