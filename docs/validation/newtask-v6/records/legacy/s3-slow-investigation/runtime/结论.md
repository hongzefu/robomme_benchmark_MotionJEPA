# S3 低开销运行时调查

结论：这段真实运行在持续前进；主线程的主要采样等待点位于 NVIDIA 内核模块的读写锁。没有发现 CPU 配额、CPU 调度排队或这一窗口内 GPU 低频可解释慢速。当前证据不能定位锁持有者，也不能把整个约 8.5 倍变慢都归因于这一个等待点。

模块归属通过只读 `rg ' os_acquire_rwlock_(write|read)\s' /proc/kallsyms` 核验：两个符号均带 `[nvidia]`。没有用函数名字自行猜测其所属模块。

任务确实前进：开始时 `VideoUnmask_episode_10` HDF5 为 96 字节；结束时为 112016464 字节并出现 2782449 字节视频，同时新建 `VideoUnmask_episode_3` 的 96 字节 HDF5。这里只读取最近三个身份的文件元数据，不读取大文件内容；96 字节的新文件不算成功轨迹，文件长大和视频出现也不替代最终任务成功检查。

## 能排除与尚缺证据

这段窗口不支持「单条完全卡死」「CPU 配额节流」「CPU 调度饥饿」解释。此前已核对全部线程 affinity 为 CPU 0～31、全部 cgroup 祖先无限额；本次局部证据与之相符。GPU 频率、温度稳定，但没有 S0 同时刻等量采样，因此不作旧版和新版 GPU 性能的直接定量比较。

尚缺 NVIDIA 写锁的持有者、具体上层调用和连续等待耗时分布。`/proc/1843953/syscall` 返回 `Operation not permitted`，内核 stack 此前返回 `Permission denied`；本次不绕过权限、不附加调试器。`/proc/stat`、wchan 是先后读取，瞬间跨状态可能产生个别对应差异；31 点统计不是连续跟踪，不能把 22/31 精确当成整个任务的耗时占比。

本次没有尝试调整 GPU、电源、线程、环境变量或重启。后续若需更深层调用栈，应单独评估权限及对主线的影响；当前继续保留已有运行和监督，比无证据修改参数更可复核。
