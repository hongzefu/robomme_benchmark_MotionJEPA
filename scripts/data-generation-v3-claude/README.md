# 数据生成 v3-claude：通用 CV 规则删臂（红色遮罩可视化）

本目录回答一件事：**不碰任何仿真真值，只靠通用 computer vision 规则**，能把
RoboMME `front_rgb` 序列里的机械臂（含夹爪）删得多干净。删除的像素涂**纯红遮罩
(255,0,0)**、不填充其他像素；桌面与任务物体保留原样。产物是纯可视化（预览图 +
全帧拼接大图），**不重新仿真、不写 h5**，直接消费 `artifacts/generated/v21-16env`
里现成的 16 任务 × episode_0。

## 与 v2 / v2.1 的差异

| 方面 | v2（`data-generation-v2/`） | v2.1（`data-generation-v2.1/`） | v3-claude（本目录） |
|---|---|---|---|
| 定位机械臂 | 仿真 segmentation 白名单 | 仿真 segmentation | **纯 CV 规则，仿真真值零参与** |
| 桌面 | 涂平成纯棕 | 保留 | **保留** |
| 夹爪 | 保留手指 | 只留黑指尖 | **不保留，一并删除** |
| 删除区填充 | 纯棕色 | 纯色 | **纯红遮罩，不填充** |
| 链路形态 | 生成时写入 h5 | 生成时写入 h5 | **离线后处理，只出图** |
| 时序 | 全帧 | 全帧 | **时序降采样 4 倍**（每 4 个 timestep 取 1 帧） |

## 口径（用户逐条拍板）

1. **纯 CV 定位**：找臂只用通用图像规则（静止相机背景差分 + 触边连通域 + 无彩
   先验），仿真 segmentation 一律不碰——现成 h5 里本来也没有落盘。该口径由
   `tests/lightweight/test_arm_removal_logic.py` 的 AST 防火墙在结构上钉死
   （import 白名单 + 分割相关标识符禁用）。
2. **红色遮罩、不填充**：判定为臂/阴影的像素涂 (255,0,0)，其余像素与原图逐位相同。
3. **连阴影一起删**（等比压暗判据）。
4. **被夹持物体尽量保护**：`protect_saturated` 默认开，臂 mask 内高饱和连通子区域
   （红/蓝/绿方块、靶环等）挖回保留。低饱和被操作物（MoveCube 粉棕棍其实 S≈90
   能保住，真救不了的是 RouteStick 白色缆线、白色按钮这类无彩物）与臂不可分，
   属已知代价。
5. **多删可接受、漏删不可接受**：目标是「尽可能删除干净」，露出背景的误差分
   （见下「已知限制」）一律往删的方向偏。
6. 时序降采样 4 倍；空间保持 256×256；产物放本目录 `outputs/` 内部。

## 算法（`arm_removal.py`，纯 numpy + cv2）

按 `is_video_demo` 相位切段（demo/执行两相位间场景重摆、背景板必须分段建），
段内流程：

1. **众数背景板**：逐像素取时间轴众数（分块 RGB 打包 uint32 排序求最长游程）。
   渲染确定性极强（实测 86% 像素跨 291 帧逐位重复、无 ±1 噪声），背景是唯一
   高频重复值，众数天然免疫「被臂遮挡超半程」——中值在这类像素上会给错值。
2. **前景**：与背景板逐通道最大绝对差 > `diff_threshold`(8)，3×3 闭运算 +
   floodFill 填洞（种子取四角第一个非前景角）。
3. **臂外观模型（从数据学）**：触边前景连通域腐蚀×2 取核心，饱和度阈值
   `s_thr = median + 3·MAD + 6`、硬上限 20（实测臂核心 S≈4、地面棋盘带 S≈23、
   桌面 S≈160，20 是唯一安全分界；不用高分位——臂夹着高饱和物体时分位数会被
   污染到 158）。核心样本不足时用检出的底座区增强种子做**二轮学习**。
4. **顶部常驻无彩区（底座+臂 home 长驻痕迹）**：背景差分对全程不动的区域天然
   失明，在背景板上按「无彩且够亮 + 触顶带 + 宽度 ≤128 + 面积 ∈[60,6000]」检出，
   整块恒红。白色任务物体靠「必须触顶」排除、地面棋盘带靠宽度上限排除。亮度
   下限设独立上限 `occluder_val_cap`(160)——它只为排暗色背景物，不得高到把灰白
   底座挡在外面。
5. **臂长驻污染区（stuck）规则**：背景板呈臂色（无彩）且时间不稳定（众数占比
   <0.95）的像素属污染区——臂回到常驻位姿时与板同色（黑洞漏检）。当前帧仍是
   臂色的污染区像素并入前景候选，由锚定的连通性把关；恒定的无彩静止物（白按钮）
   众数占比≈1，不受影响。
6. **逐帧臂判定三级**：①锚定——触 top/left/right 边带或常驻区的前景连通域
   （臂不一定从顶边入画：RouteStick 首帧夹爪从右缘探入）；②碎片吸附——距主体
   ≤12px、臂色一致度 ≥0.6、面积 ≤1500 的小碎片；③阴影——逐通道等比压暗
   （比值均值 ∈[0.55,0.97] 且通道比值 std<0.06，限臂 6px 邻域）。
7. **protect**：臂 mask 内 S≥60 且面积 ≥20 的连通子区域挖回。候选域限定在
   **膨胀前的臂主体且排除阴影**——桌面阴影是等比压暗的高饱和棕，不排除会把
   阴影系统性「保护」回来；膨胀扩张带是臂边缘混色，不排除会在臂边缘挖出残留环。
8. 最终 mask 3×3 膨胀 ×2，`apply_red_mask` 涂红。

参数唯一真源是 [`arm_removal_params.json`](arm_removal_params.json)（当前即收敛
值：默认参数一轮目视达标，未再调参），全部参数含义见 `ArmRemovalParams` 的
逐字段注释。

## 用法

```bash
# 16 任务全量（约 26 秒，纯 CPU）
uv run --no-sync python scripts/data-generation-v3-claude/render_masked_outputs.py \
  --h5 artifacts/generated/v21-16env/record_dataset_*.h5

# 单任务调参试跑（--set 覆写参数，--write-back 收敛后写回 json）
uv run --no-sync python scripts/data-generation-v3-claude/render_masked_outputs.py \
  --h5 artifacts/generated/v21-16env/record_dataset_MoveCube.h5 \
  --set diff_threshold=6 --set arm_dilate=3

# 单元测试（并入仓库默认档）
uv run --no-sync python -m pytest tests/lightweight/test_arm_removal_logic.py -q
```

产物写到 `outputs/`：

- `<Task>_ep0_preview.png`：均匀抽 6 帧的三联网格（原图 | 红遮罩图 | 纯 mask，
  白=删除）。第三联是必须的：红遮罩与红色任务物体撞色，只看第二联分不清。
- `<Task>_ep0_grid.png`：全部抽样帧的红遮罩网格拼接大图（每行 8 帧、原始分辨率），
  时序稳定性靠它判读（用户口径：不出视频、出拼接图片）。**单张可达 29MB，
  不入 git**，用上面第一条命令随时重新生成。
- `summary.json`：逐任务 stats（段数、常驻区 bbox、删除占比、protect 挖回像素数
  等）+ 生效参数 + 常驻区 bbox 跨任务参考对照。

## 实测结论（2026-08-10，16 任务 × episode_0，时序 4×）

- 全部跑通：抽帧后 24–300 帧/任务，单任务 0.35–3.7 秒，合计约 26 秒；
- 删除占比均值 3.4%–11.7%（demo 相位臂大范围伸展的任务偏高）；
- 常驻区 bbox：13/16 任务完全一致 `[0,29,110,146]`（同一机器人同一相机的自证）；
  PatternLock `[0,53,91,169]`、PickXtimes/StopCube 左扩、VideoRepick 右下扩——
  均为该任务臂/装置长驻痕迹更大所致，目视确认非误检；
- 16 张 preview + 抽查 grid 逐张目视：臂主体、夹爪、腕相机支架、stick 细棍全部
  删净且时序稳定无闪烁；任务物体（方块、按钮、靶环、bin、彩色柱）非接触帧
  零误删；被夹持的红/蓝/绿方块与靶环被 protect 稳定挖回；桌面木纹、光泽渐变、
  地面棋盘带完好。

### 已知限制（均为「多删」向或接触帧连带，符合口径）

1. **臂 home 位姿的空心轮廓多删**：臂长驻位置的背景板被臂色污染，臂离开后露出
   的真背景差分大、被当臂删掉，画面上是一圈稳定的细红轮廓（各任务普遍、轻微；
   VideoUnmask demo 段最明显）。属「多删可接受」口径，不影响臂本体判读。
2. **PatternLock 部分按钮被吸附**：白色小按钮无彩、与 stick 尖距离近时被碎片
   吸附规则纳入（接触帧连带语义）。收紧吸附参数会伤 RouteStick 的真臂碎片，
   不调。
3. **StopCube 左上黑色任务装置有红轮廓**：无彩+触顶+常驻，通用 CV 规则与臂
   不可分，轻微多删。
4. **RouteStick 白色缆线被删**：被 stick 拖动、无彩，protect（高饱和判据）救
   不了，与「白按钮被夹爪按压时连带」同属低饱和被操作物的已知代价。
5. **SwingXtimes 摆动帧的孤立红块**：像素级核查为摆动中的夹爪灰色指节（该删），
   方块本体被夹爪遮挡、可见红色像素不足 protect 面积门槛（20px），非误删。

### 调参过程记录（单测驱动 + 目视迭代各一轮）

- 合成单测抓出三个真缺陷并已修：①外观模型 `v_min` 采样偏差会反把底座挡在
  「够亮」判据外（加 `occluder_val_cap` 解耦）；②桌面阴影高饱和、会被 protect
  「保护」回来（protect 候选域排除阴影与膨胀带）；③臂根长驻污染区黑洞
  （stuck 规则）。
- 16 任务第一轮目视抓出：PatternLock 常驻块整块被面积上限拒绝 → 曾试「按众数
  占比剔除污染区只留纯底座」，实测底座本体被臂划过后 fraction 同样偏低、被剔碎
  成 None，弃用；改为把常驻区语义扩为「底座+长驻痕迹整块」（面积上限 2600→6000），
  13/16 任务 bbox 一致、其余三任务扩块目视确认合理。
