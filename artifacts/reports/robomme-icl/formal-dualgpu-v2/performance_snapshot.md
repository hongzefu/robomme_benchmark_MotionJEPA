# 双 GPU、32 worker 正式认证的一次性性能快照

本报告使用已有日志作一次性分析，GPU 与 iostat 统计的观测截止为**日志时间 2026-09-07 23:04:57**。没有改动源码、启动新的长期监控或终止任何进程。正式会话为 `gen-icl-cert96-dualgpu-20260907-v2`，主 bash PID 为 `3687873`，启动基线为 `f2500c6fa91e9019e96aec819f4e08c2c9e5bbd9`。

当前窗口没有 CPU 总体算满、磁盘队列拥塞或显存耗尽的证据；多个物理进程确实在 NVIDIA 驱动的写锁处等待，这是本次最明确的并发等待证据。**尚未做相同规格的 16 worker 对照，不能认定 32 worker 最优，也不能仅凭 GPU 利用率较低宣称没有瓶颈。** 本性能检查没有修改执行计划；运行随后因独立发现BinFill候选预填孔的边界而优雅中断，退出130，详细状态见 [stop_result.json](stop_result.json)，不能将本快照解释为全量认证完成。

## 数据来源与统计口径

- [run_context.json](run_context.json)：正式运行配置与来源记录。
- [gpu_samples.csv](gpu_samples.csv)：两张 GPU 从 23:00:31 开始的完整采样；截至本快照每卡 466 点。
- [iostat.log](iostat.log)：CPU 与磁盘区间统计；全窗口统计排除首个累计报告，另取最近 30 个约 2 秒区间。
- [certification96.log](certification96.log)：已完成物理运行的 `ICL_TIMING`、严格比较的 `ICL_VERIFY`、认证进度和失败类型。
- 一次 `ps` 与一次 `nvidia-smi -q -x` 取得进程及 GPU 上下文快照；随后只读取该批已记录 PID 的 `/proc/<pid>/wchan`，没有再次遍历进程列表或固定轮询。
- 单次 `lscpu`、`/proc/stat`、主进程 affinity 与 cgroup 信息确认 CPU 分母；`findmnt` 与 `lsblk` 确认存储介质。

配置为 32 个 slot worker，每个物理环境 `num_envs=1`，每个物理子进程处理一条 episode。两卡按 seed 固定绑定，每卡物理并发上限为 16。GPU 采样名义间隔为 500 ms，但实际每卡平均间隔为 **0.572 秒**；下面报告样本均值和 0% 采样占比，不把名义频率当作硬件计数器分辨率。

## CPU 分母与等待状态

| 项目 | 实测结果 |
| --- | --- |
| CPU 型号 | AMD EPYC 9334 32-Core Processor |
| 在线逻辑 CPU | `lscpu` 与 `/proc/stat` 均为 32，编号 `0-31` |

因此这里不是“80 个逻辑 CPU 中仅允许使用 32 个”的情况，iostat 的分母与任务可用 CPU 集合一致。

| CPU 指标 | 排除首个累计报告的全窗口均值 | 最近约 60 秒均值 |
| --- | ---: | ---: |
| user | 21.426% | 23.717% |
| system | 14.213% | 14.373% |
| iowait | 0.0030% | 0.0027% |
| idle | 64.359% | 61.910% |

最近窗口 user 与 system 合计约占 12.19 个 CPU 的计算时间，说明全部 32 个可用 CPU 总体没有算满；这不排除局部串行路径或锁等待。快照 CPU PSI `some avg60=1.04%`，IO 与 memory PSI 的 `avg10/avg60/avg300` 均为 0。

单次进程快照发现 30 个内层物理子进程，其中 22 个为 D 态、5 个为 R 态、3 个为 S 态。随后针对这批记录中的 D 态 PID 查询，20 个目标中已有 11 个退出；剩余 9 个中有 **8 个等待在 `os_acquire_rwlock_write`**，另一个当时未阻塞。`/proc/kallsyms` 明确将该符号归属为 `[nvidia]`。

这些等待与当时接近零的磁盘 iowait、很低的 NVMe 队列占用共同表明，不能把 D 态简单归因于磁盘读取。NVIDIA 驱动锁或上下文同步是当前最明确的等待方向。内核调用栈读取返回 `PermissionError`，因此未取得持锁方调用栈，也不能确定等待只发生于构建阶段。进程退出与上述 wchan 查询属于后续定向检查，不应伪装成同一时刻的完整采样分布。

显存占用包含系统及其他上下文，不能全部算作当前任务的独占显存。该窗口未出现 OOM，也没有接近每卡约 46 GiB 容量的证据。

**NVIDIA 上下文条目数不等于绑定到该卡的任务数。** 单次快照的 30 个物理子进程中，26 个已经建立完整主上下文：按 `C+G` 类型及约 738–743 MiB 的主要占用，可识别 GPU 0 和 GPU 1 各 13 个。GPU 1 的这些进程还会在 GPU 0 上出现约 6 MiB 的 `G` 上下文，所以 GPU 0 列表表面上有 26 个条目，不能解释成 26 个 GPU 0 任务。

另外 4 个物理子进程尚未在 GPU 列表中出现完整主上下文，可能处于构建或收尾；当前证据不能精确确认它们各自的绑定。结合每卡最多 16 个物理进程的信号量与总计 30 个在途进程，分配应位于 `14/16` 到 `16/14` 之间，符合“约 15/15”，但不能把 **15/15** 写成已实测的精确值。

## 本地 NVMe 与主机内存

仓库所在 `/data` 为 `/dev/nvme1n1p1` 上的 ext4，底层设备为 **Micron 7450 NVMe SSD**（`Micron_7450_MTFDKCC15T3TFR`、`ROTA=0`）；不是 NFS。系统盘为另一个 Samsung NVMe，此处的数据盘指标单独列出。

| 数据盘指标 | 最近约 60 秒区间均值 | 该窗口峰值 |
| --- | ---: | ---: |
| 写入带宽 | 79.40 MiB/s | 579.09 MiB/s |
| 读取带宽 | 29.47 KiB/s | 140 KiB/s |
| `%util` | 1.225% | 9.7% |
| `w_await` | 0.138 ms | 0.44 ms |
| `r_await` | 0.145 ms | 0.5 ms |

这些是区间值的简单平均，设备因空闲未显示的区间按零处理；不是按请求数量重新加权的总体请求延迟。HDF5 读取还可能命中页缓存，因此“块设备读取很低”不等于没有 HDF5 解码或内存拷贝开销。当前数据盘未呈现吞吐或队列饱和迹象。

快照 `MemAvailable` 约 **296.1 GiB**，任务进程族 RSS 合计约 **49.36 GiB**；RSS 直接相加包含共享页重复计数，不是独占内存或 PSS。Swap 接近已用满，但本次 memory PSI 为零且可用内存充足；没有 swap-in/swap-out 速率证据，不能据此认定本次运行发生换页抖动。

## 已完成运行的分阶段耗时与进展

截至统计截断点，共有 **46 次完整 `ICL_TIMING`、覆盖 32 个 seed**；GPU 0 与 GPU 1 各 23 次。下面只统计已经成功完成并写出该日志的物理运行，不包含尚未结束的任务或被拒绝候选的完整成本。

同一截断点有 13 条双进程严格认证通过、22 次正常候选拒绝，基础设施重试、严格复现差异和 OOM 计数均为 0。候选拒绝包括机械臂与场景对象的非预期碰撞；这是当前不可行候选筛选记录，不能等同于资源压力错误。

## 结论边界与后续对照

本次记录支持“当前显存、主机内存及磁盘没有耗尽或拥塞迹象，CPU 总体未算满，同时存在明确 NVIDIA 驱动写锁等待”。它不足以证明 32 worker 已达到最佳吞吐，也不足以确定减少 worker 后必然更快。

现有 `ICL_TIMING` 仅含整条运行的阶段耗时，没有可与 GPU 采样对齐的逐控制步起止时间，因此**没有慢步与非慢步的 GPU 利用率分层证据**。本报告没有用中位数或某个单点替代这些缺失证据。

按当前决定，先保留既定 32 worker 脚本完成整个闭环，不中断正在成功的认证。之后再在相同机器、相同 NVMe、相同已认证 spec 与原 GPU 绑定下做匹配的 16/32 worker 对照，分别记录预热、稳态吞吐、利用率均值与 0% 占比，以及每条 `build/run/write` 耗时。认证有两次实跑和额外比较，而生成只有一次实跑，二者的总墙钟时长不能直接当作相同工作量的比较。
