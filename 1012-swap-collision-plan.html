二、机制：加了哪些函数、各自干什么

一句话版：reset 时用纯几何把 S 段交换全部预演一遍并证明不撞，把配对写死；运行时只做复核。 新代码分三层：vendored 判据（不改）、新写的规划函数（swap_plan.py）、挂到三个子类上的混入类。下面逐个说清每个函数的输入、输出、在哪被调用、失败时做什么。

2.2 第二层：新写的规划函数（src/robomme_xhard/swap_plan.py）

函数 输入 输出 作用 失败时
select_initiator(usage, excluded, generator) usage：每个对象至今参与次数（发起 + 搭档）列表；excluded：上一段刚换过的两个序号；子类独立 torch.Generator 本段发起者序号 K3/K4 新规则：候选池 = 全部 − excluded，池空则回退全部；取 usage 最小者；并列时用 generator 随机抽一个 不会失败（N ≥ 2 由上游保证）
nearest_partner(index, xy) 发起者序号 + 当前位姿表 {序号: (x, y)} 搭档序号 K2 不变：照抄 v2.1 specs.py::_nearest_partner，平面距离严格小于、等距取序号小者 无候选抛 ValueError（N < 2）
plan_swaps(states, bystanders, swap_times, generator) 全部交换对象的 ObjectState、旁观者、S、generator SwapPlan(pairs=[(a, b, distance_m, min_gap_m)…], usage, initial_gap) 预演 S 段：循环 k = 1…S：select_initiator → nearest_partner → check_swap_sweep(cur[a], cur[b], 其余对象 + bystanders) → usage[a] += 1, usage[b] += 1 → 位姿表互换（a 落到 b 的 xy 并接手 b 的朝向，z 各自保留，与 swap_flat_two_lane 收尾一致）。照搬 v2.1 _simulate_swaps，只把发起者来源换成 select_initiator 任一段 check_swap_sweep 拒绝 → raise SwapCollisionError(rejection, stage="sweep")

2.4 两个异常（src/robomme_xhard/collision/__init__.py）

异常 父类 携带 何时抛
SwapCollisionError SceneGenerationError rejection（CollisionRejection）、stage ∈ {initial, sweep, sweep_actual, substep_before, substep_after} 任何几何判据拒绝
SwapBindingError SceneGenerationError detail：段号、控制步、预写搭档、实算搭档、距离表 段起点实际最近邻 ≠ 预写搭档
